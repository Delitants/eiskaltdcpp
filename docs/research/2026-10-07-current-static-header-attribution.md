# Current Static Library And Header Attribution

## Outcome

The retained both-CPU test consumers use the intended c-ares 1.34.8 and
libmaxminddb 1.13.3 static archives, but **controlled-header acceptance is HELD**.
The compiler dependency records select headers currently identifying c-ares
1.34.4 from a different shared installation on both CPUs. Apple Silicon also
selects a differently generated MaxMind configuration header outside the
controlled prefix.

This is a newly established build-input isolation gap, not a proven cause of the
historical crash, shutdown refusal or network failures. No product behavior or
dependency installation is changed. The next bounded repair must establish
matching provider headers in fresh build trees and rerun the affected tests.

Audit base is `3ac433695` plus the unchanged seven-file local repair. The retained
matrix consumers predate this documentation and the latest catalog repair; they
are not fresh builds of every current source. Evidence is retained under
`Work/qa/current-static-consumption-20261007/`.

## Header Isolation Failure

The actual `ProxyResolver.cpp.o.d` and `Util.cpp.o.d` records identify six relevant
headers per CPU. Fresh preprocessing with the retained compiler commands selects
the same physical paths. Across those twelve headers the strict gate reports
exactly **17 errors: seven byte mismatches and ten uncontrolled origins**.
The separate acceptance command exits with failure and that exact inventory;
successful audit execution does not count as a passed header gate.

| Header Set | Both-CPU Findings |
| --- | --- |
| `ares.h`, `ares_version.h`, `ares_dns_record.h` | Shared 1.34.4 headers, not matching the selected 1.34.8 provider; six byte and six origin errors. |
| `ares_build.h` | Bytes match, but both origins are outside the selected provider prefix. |
| Apple Silicon `maxminddb.h` | Bytes match upstream, but origin is outside the controlled prefix. |
| Apple Silicon `maxminddb_config.h` | Different generated bytes and uncontrolled origin. |
| Intel MaxMind headers | Both match the selected provider's controlled files. |

The MaxMind difference includes explicitly defined zero macros versus undefined
macros. Different bytes alone do not establish an incompatible ABI or observable
runtime failure; no such claim is made.

Clang places the shared local include directory ahead of the selected imported
system-header directories. The Apple Silicon flags additionally place the shared
Homebrew system-header directory before the controlled static prefix. Therefore
choosing the right library or setting `MAXMINDDB_INCLUDE_DIR` does not by itself
guarantee the right header is selected.

## Causal Control And Checks

The initial disposable preprocessing control only prepended `-I` for the chosen
prefix. It failed: Clang treats a directory also present as `-isystem` as a system
directory and does not move it to the requested position. The original script,
failure and compiler output are retained, not replaced by a passing receipt.

The corrected private control removes only the equivalent system include entry
and prepends the controlled non-system directory. Both CPUs then select all six
matching controlled headers. No original compile command, build object or binary
is changed. This supports the include-order diagnosis; it is not the CMake repair
or release acceptance.

Review identified incomplete report-inventory checking and insufficient retry
protection in the private harness. Four new regressions fail on exactly those
gaps before correction, without unrelated errors or skips. The final ten-test
suite passes: nine report-contract tests plus a disposable-file diagnostic
overwrite refusal. The report tests cover the exact original failure inventory,
omitted static input, wrong archive/source archive, substituted header bytes,
wrong origin, missing CPU/header inventories and empty static-input payloads.
The acceptance command recomputes the complete report errors rather than trusting
the saved status. The original seventeen-error inventory remains unchanged.

The report mutations are explicitly report-level unit controls, not provider
filesystem tamper tests. Only the retry test uses a disposable local file. A
normalized report control cannot waive the actual held header result. Original
and corrected preprocessing artifacts, first failed probe, RED regressions and
the intermediate failed cross-field check remain retained.

The input inventory records 720 current readback hashes. These hashes and retained
dependency listings are not immutable pre-compilation snapshots of historical
header bytes. The generated main-app link rules have no corresponding executable
in these matrix trees; they are not counted as built app consumers.
