# Shadowsocks 2022 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:test-driven-development` for each task and `superpowers:verification-before-completion` before claiming completion.

**Goal:** Add interoperable TCP and UDP support for `2022-blake3-aes-128-gcm`, `2022-blake3-aes-256-gcm`, and `2022-blake3-chacha20-poly1305`, including Extensible Identity Headers (EIH).

**Architecture:** Keep legacy Shadowsocks AEAD behavior isolated. Add a dedicated Shadowsocks 2022 codec with explicit TCP encoder/decoder state and UDP session/replay state. Vendor the official portable BLAKE3 C implementation, implement XChaCha20-Poly1305 with HChaCha20 plus OpenSSL ChaCha20-Poly1305, and let `Socket` dispatch by parsed method. Password fields accept the standard colon-separated identity-PSK chain followed by the user PSK.

**Tech Stack:** C++17, OpenSSL EVP, portable BLAKE3 C, official Shadowsocks 2022 wire specifications, Catch2.

**Primary specifications:**
- `https://github.com/Shadowsocks-NET/shadowsocks-specs/blob/main/2022-1-shadowsocks-2022-edition.md`
- `https://github.com/Shadowsocks-NET/shadowsocks-specs/blob/main/2022-2-shadowsocks-2022-extensible-identity-headers.md`
- `https://github.com/BLAKE3-team/BLAKE3/tree/master/c`

## Task 4: Implement Shadowsocks 2022 UDP sessions and replay protection

**Files:**
- Modify: `dcpp/Shadowsocks2022.h`
- Modify: `dcpp/Shadowsocks2022.cpp`
- Modify: `tests/qt/test_shadowsocks2022.cpp`

- [ ] AES request packet:
  - 16-byte separate header (`clientSessionId`, u64be packetId) AES-block-encrypted with the PSK;
  - derive the body subkey from PSK + session ID;
  - use separate-header bytes 4..15 as the AEAD nonce;
  - encode `type=0`, timestamp, padding length/padding, target address, payload.
- [ ] AES response body must validate `type=1`, timestamp, and echoed client session ID.
- [ ] ChaCha request packet: 24-byte random XChaCha nonce followed by authenticated body containing client session ID, packet ID, request header, and payload.
