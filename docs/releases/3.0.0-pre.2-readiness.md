catalog tests and documentation are updated.

unwanted relaunch were checked.

Eight real-GOST interoperability cases pass per CPU using disposable local
servers and identities. Production proxy settings and credentials are not

Offline packaging regressions pass: 30 release-profile tests, 21 dependency
closure tests, three dylib-ID assertion groups, nine metadata tests, seven

## Limits And Retained Evidence

Testing ran on macOS 27.0, with Intel execution under Rosetta. Physical Intel
and native macOS 14/26 runtime acceptance remain unverified. Wider Windows/Linux
testing, native-speaker review and optional Developer ID signing/notarization
remain future work. Whole-archive dependency reproducibility is not claimed.
No VM is a release requirement.

Two initial packaging-suite failures were caused by Xcode compiler discovery
inside the command sandbox. Their logs are retained. Explicit native reruns
passed with the required isolated fixture inputs. An intermediate packaging
invocation lacking those inputs skipped the suite and is not acceptance evidence.

An initial Intel Torrent suite had one loopback transfer miss its 10-second
seeding deadline while other builds/tests were active. The unchanged case passed
three isolated repetitions, followed by a complete unchanged 167-case Torrent
suite pass. The original failure is retained; no source or deadline was changed.
At release qualification, the precise cause of that deadline miss was not yet
established; the test-only follow-up below records the subsequent investigation.

An ARM allocation-failure test initially aborted in the loader because its
test-only interposer target had not been built. After explicitly building that
excluded-from-defaults target, the isolated allocation-failure case passed.
The initial loader failure is retained and is not counted as a product-test pass.

The first public-feed verification invocation was refused because its directory
also contained the downloaded manifest. The original refusal is retained;
verification passed using the same downloaded feed bytes in the required
XML-only directory. No feed contents, trust keys or verification rules changed.

## Post-Release Listener Test Repair

Subsequent investigation reproduced the same seeding assertion failure with two
unchanged Intel test processes, and with concurrent unchanged ARM/Intel tests.
The native disk probe bypassed normal session randomization and reused fixed
loopback port 49171. A reserved-port control recorded `EADDRINUSE`, a zero seed
listener port and expiry of the unchanged 10-second transfer wait. The original
release-run XML lacked endpoint diagnostics, so its particular bind failure is
not retrospectively proven by that older record alone.

The maintained test helper now requests an OS-assigned port only in a copy of
its native session settings. Engine configuration, user validation, production
binding/fallback policy and payload deadlines are unchanged. The peer-transfer
case waits for a nonzero listener endpoint before connecting. A new regression
keeps a real configured port occupied while checking that two probe sessions
obtain distinct usable ports and retain their original configuration.

That regression was observed failing before the helper repair, with native
`system:48` and `firstPort == 0`. Three concurrent ARM/Intel pairs then passed
both the regression and original transfer case. Both complete updated Torrent
backend suites passed 168 cases and 18,703 assertions each, with no failures or
skips, under their existing 600-second aggregate deadline and loopback-only
network policy. Independent static review found no material issues.

Both repaired test executables were compiled from the maintained test source,
using the matching unchanged release runtime objects. ARM execution was native;
Intel execution used Rosetta. No other application suites were rerun for this
test-only follow-up. Existing compile-time peer-info deprecation warnings remain
unrelated and unchanged. Local evidence is retained under
`Work/qa/listener-repair-20261017.RNmXQalk/`.

No application runtime files, installed app/profile, release tag/assets or signed
updater feeds changed. This follow-up does not replace the released application
source or the release qualification results above.

## Local Installation

The Apple Silicon package was installed at `/Applications/EiskaltDC++.app` using
an atomic, reversible same-filesystem swap. The previous app and a post-quit
profile snapshot are retained in a private local backup directory. Profile
contents compare unchanged after installation. Strict signatures, all 89 Mach-O
images, version/build metadata and LaunchServices handler registration pass.
Existing default application choices were not taken over.
The installed executable also passes isolated Cocoa startup with networking
denied, a disposable profile and no external dependency overrides. The user's
normal application session is left closed.

The first install attempt stopped on the application's exit confirmation before
any replacement. The confirmation was accepted, native process checks established
normal exit, and a fresh backed-up attempt completed. No process was force-killed.
The first attempt and its unused prepared stage are retained as local evidence.

Local evidence is retained under `Work/qa/release-build-20261017/`; private QA
profiles, credentials and unrelated untracked files are not published.
